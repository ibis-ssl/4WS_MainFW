# 電源基板・キッカー・ドリブラーの操作

電源基板はCAN2。通常給電の開始前に、Orionの保護値（最低15 V／最高35 V、最大50 A、FET／コイル各90℃）を `0x010` で送る。現行の `F303_boost` は設定値を受信して保持する。実際の過電流・低電圧の保護判定には同FWの固定しきい値も使われる。Mainの送信受理から実保護値の適用は判断できない。

- バッテリー通知 `0x215` が200 ms途絶すると走行、操舵、キッカー、ドリブラーの操作を停止する。通常給電のPowerOnは継続する。操作の復帰には新しい通知とボタン解放が必要。
- UART `KICKER` の `Lo` はバッテリー通知が22.5 V未満、`Hi` はFETまたはコイルが70℃超、`To` はバッテリー通知の途絶を示す。低電圧／高温は黄色で表示し、2秒間隔で短音を鳴らす。
- 電源Faultでは `0x000` を両CANへ各1回通知して、PowerOffに切り替える。Fault中に中央ボタンを500 ms長押しするとCAN2の電源リセット要求を1回送る。MainのFault保持はMain再起動で解除する。
- UART `MOUSE` はCAN2の `0x241`（DLC 6または8）から符号付き相対X／Yとqualityを表示する。オドメトリーへの組込みは未実装。

## モードスイッチの動作試験

SW7のコードは接点閉成を1としたDIP_0～3の合計。テストモード選択後、ボタンを離して30 ms以上待つ。給電、周辺基板の起動確認と電源帰還が有効な間だけ操作できる。

| SW7 | 操作 | 出力 |
|---|---|---|
| `4` ドリブラー | 中央を押している間 | Orion互換のCAN1 `0x104` に20% Duty、直近のボール検出ありなら50%。CAN1の旧ドリブラー帰還 `0x204` が必要。解放・離脱・帰還断で0%。ESC PWMの仕様確定と実機ドリブラーの接続確認は別項目。 |
| `5` キッカー自動 | 上で充電。中央でストレート、下でチップ | CAN2で目標100 V。直近のボール検出があり、実電圧が90～110 Vのときだけ、押下1回につき出力50%（127/255）。 |
| `6` キッカー手動 | 上で充電。中央でストレート、下でチップ | 目標100 V、実電圧90～110 V、押下1回につき出力50%。ボール検出を条件にしない。 |

4WSでは上を押すまで充電を開始しない。充電開始から15秒、モード切替、電源状態・電圧帰還の途絶、Fault、FW更新のいずれかで充電許可を解除する。発射間隔は500 ms以上。100 V・50%は指令値で、実際の電圧や機構の動作はホスト試験の対象外。

## 電源FW照会・更新

[MainのRTTサーバー](atlas_bringup.md#mainのrtt)に接続して実行する。実CM4 SPIからの更新コマンドは未実装。

```powershell
python ./Script/main_debug_rtt.py power-version
python ./Script/main_debug_rtt.py --log ./build/hardware/power-update.jsonl power-update PATH_TO_F303_BOOST_APP_BIN
```

ノード100の `0x611`／`0x6C4` でビルドIDとCRC32Cを照会する。更新には `F303_boost` のスタンプ済みアプリBINを使用する。Mainは出力停止後の `0x244` を複数回確認してから既存OFWブートへ移行し、896バイト単位で転送する。確定応答が失われた場合はブートローダーの確定位置を読む。再起動後はアプリの電源通知とビルドID・CRC32Cを照合する。ブート移行要求を送った後に失敗した場合はMainで通常給電を停止したままにし、同じ経路から再実行できる。更新とテスト操作を同時に開始できない。
