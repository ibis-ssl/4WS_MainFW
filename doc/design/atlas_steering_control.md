# Atlasステア：状態・基板制御・初期角度校正通知

2026-11-18。**接続設計。ステアFW/PCは実装・1基板実機確認済み。Main未対応。**

2026-11-18実装状況：ステアFW/PCを通常CAN・限定RTTへ移行し、1基板M0/M1の初期化・5°指令・同時Duty・通信途絶停止/復帰を確認した。Main実装・混在バス・2基板同時実機は未確認。[ステア現行仕様](https://github.com/ibis-ssl/G474_SWCLDvier/blob/dev/dual_board/doc/can_protocol.md)を参照。
IDと高速数値形式は[Classic通信設計](atlas_can_classic16.md)、全体の入口は[CAN詳細](atlas_can.md)。本書の基板制御byte配置、状態番号、校正通知byte配置はレビュー用の仮定義。

## 確定した動作条件

- 角度指令0x120/0x122、Duty指令0x130/0x132、角度＋電流帰還0x230/0x232を500 Hzとする。指令は現在モードの一方だけを送る。
- 温度0x290/0x292は1 Hz、基板制御0x350/0x352は10 Hz。いずれも対象の先頭ステア番号をIDの下位桁へ割り当て、後続軸のIDを空ける。
- 出力指令の最終有効受信から100 ms以上、または基板制御の最終有効受信から500 ms以上でcoast停止する。起動後の未受信も指令なしとして停止する。受信しただけの不正なDLC/値やモード不一致指令は期限を更新しない。
- 通信途絶はFAULTにせず、共通0x000のエラーとして通知しない。両通信が新鮮になり、有効な駆動指令・正の両上限・初期化等の条件が揃えば自動復帰する。リセットや再許可操作は要求しない。
- 基板制御途絶時は古い出力指令を無効にする。復帰後の制御モードに対応する出力指令を受けてから再開する。出力指令途絶だけなら、モードは保持して次の有効出力指令で再開する。
- 上限0、明示停止、通信途絶、エラー検出時の停止はcoast。角度保持や電気ブレーキを停止動作として使わない。
- エンコーダー角度エラー・温度異常等のエラーを検出した場合は、HW故障かどうかを判定せず、基板全体でラッチしたFAULTとなる。M0/M1/基板共通部のいずれか1か所でもエラーがあれば両軸をcoast停止し、MCUリセットまで復帰しない。正常値への復帰・CAN再接続・モード変更では解除しない。リセット後も異常があれば再度FAULTとなる。
- 温度閾値、角度異常判定の閾値・継続時間は別途確定する。温度入力が未実装の場合に温度保護が成立したと扱わない。

## 角度の意味

SPIエンコーダーは誤差を含むが信用できる実操舵角の絶対基準、ABエンコーダーはモーターシャフト側の内部制御値という役割である。内部の位置制御には現行どおりABを使う。SPIによる実角度の観測・基準と、ABによる内部制御を混同しない。
この記載は意図と責務の定義であり、SPI位置制御への置換は行わない。現行の制御・校正実装は維持する。AB count/CPRそのものを通常CANの実操舵角として公開するものではない。

将来の外部角度表現についての仮の座標定義（現在の内部制御式の変更指示ではない）：初期角度校正で記録したSPIの連続角を`theta_init`とし、`theta_steer = theta_spi_continuous - theta_init`。初期校正時の基準姿勢を操舵角0とする。初期化結果を保持する間は同じアンラップ基準を使い、±πへ折り返さない。
基準姿勢を機械中立とするか、正方向と車輪位置の対応、起動時の回転数確定方法は未確定。初期校正が無効なら角度指令を許可せず、帰還角度は0x8000とする案。ABから有効角度を代用しない。

## 基板制御案：要求状態を繰り返し送る

ID 0x350/0x352、Main→ステア、DLC2、10 Hz＋変更時。byte0=M0要求、byte1=M1要求。各byteは同じ列挙値を使い、version・sequence・maskを追加しない。将来の1軸基板でのDLC・ID割当はまだ定義しない。

| 値 | 要求 | 動作案 |
|---:|---|---|
| 0 | COAST | 対象軸を停止。出力指令を無効化 |
| 1 | ANGLE | 初期角度校正が有効なら角度制御待機。対応する新鮮な角度指令で駆動 |
| 2 | DUTY | Duty制御待機。対応する新鮮なDuty指令で駆動。初期角度校正なしでも許可する案 |
| 3 | INITIALIZE | SPI初期角度校正を要求。後述の1回実行ルールを適用 |
| 4〜255 | 未定義 | パケット全体を拒否。期限も更新しない |

モード変更時は旧モードの出力指令を破棄し、新モードに一致する後続の出力指令を待つ。同じ要求の繰り返しでは指令を破棄しない。FAULTは全要求に優先する。
INITIALIZEは要求が3へ変わったときに1回だけ開始し、同じ3の定期受信で校正を再実行しない。完了後はCOASTで待機し、ANGLE/DUTY要求へ切り替えて運転する。
初期化中のCOAST要求は中断する。他モードへ直接変更された場合もまず中断してcoastとし、その後の対応指令を待つ案。
初期化が通信途絶で中断した場合は自動で探索駆動を再実行しない。通信復帰後は一度COASTを指定してからINITIALIZEを指定し直す。通常駆動の通信復帰とは区別する。
探索Duty・電流・時間制限等は保存された初期化設定を使う案で、このDLC2に追加しない。保存設定の妥当性が未確認なら初期化を開始しない。
Flash保存・MCUリセット・エラー解除を定期制御の値へ含めない。これらの保守コマンドは必要になった時点で別途定義し、FAULT解除コマンドは設けない。

## 観測状態案

要求状態と実際の状態を区別する。実状態は次の校正通知内で各軸1 byteを通知する案。正常状態用の新しい0x270系IDは設けない。

| 値 | 状態 | 意味 |
|---:|---|---|
| 0 | BOOT | 起動処理中 |
| 1 | UNINITIALIZED | SPI初期角度校正が無効で、coast中 |
| 2 | INITIALIZING | 初期角度校正の実行中 |
| 3 | COAST | 校正有効だが停止中。上限0・指令待ち・通信途絶も含む |
| 4 | ANGLE | 角度制御中（保持を含む） |
| 5 | DUTY | Dutyモードの有効指令を実行中。Duty目標0もこの状態だが出力はcoast |
| 6 | FAULT | 基板全体で保持するエラー検出状態。HW故障の確定を意味しない。両軸coast出力 |

状態の優先順位はFAULT→BOOT→INITIALIZING→駆動状態→校正有効性に応じたCOAST/UNINITIALIZED。
通信途絶専用のエラー状態は作らない。校正未完了でもDuty制御中ならDUTYを通知する。1 Hzの実状態は表示・起動確認向けであり、100 msの途絶判定を代用しない。
エラー発生箇所は診断情報として保持するが、状態の停止範囲は常に基板全体。校正通知では両軸の実状態をFAULTとする。共通0x000でロボット全体の停止へ通知する。他ノードへの停止伝搬は既存電源契約を変更せず定義する。

## SPI初期角度校正通知案

ステア→Main、ID候補0x510/0x512、DLC8、約1 Hzで要求なしに常時送る。0x511/0x513は空ける。通常駆動前・通信途絶・未校正・FAULTでもCAN送信可能なら送る。
0x500〜0x503は既存Orionのモーターパラメーター帰還のため使用しない。0x510/0x512は確認したAtlas/Orion/現行ステア定義では未使用で、現行RPCの0x5D0/0x5E0系・ステア更新0x600系・Orion更新の予約と衝突しない候補。IDを変更するのは校正通知側であり、既存FW更新IDは動かさない。

| byte | 内容 |
|---|---|
| 0..1 | M0 theta_init：int16、1 mrad、LE、無効0x8000 |
| 2 | M0 flags |
| 3 | M0実状態：上記uint8列挙値 |
| 4..5 | M1 theta_init：同上 |
| 6 | M1 flags |
| 7 | M1実状態：同上 |

flags bit0=`initial_angle_valid`、bit1=`other_config_present`、bit2〜7は0。
bit0=1は、現在のSPI角度基準と組み合わせて初期角度を利用可能なことを示す。Flashへの永続保存を意味しない。bit0=0ならtheta_initは0x8000とする。bit0=1なのに無効値なら通知を不正として扱う。
bit1=1は、その軸について追加の構成データ（例：LUT、設定済みの極性・制御ゲイン等）が保持され、デバッグ経路で参照できることを示す。追加データの有効性・現在適用中・Main取得済みは意味しない。対象項目集合は後で確定する。
全8 byteを同じスナップショットから作る。sequence・分割番号・アプリCRC・要求/ACKは付けない。Mainは各受信フレームを置き換えて利用する。
theta_initの通信量子化値でステア内部の基準値を上書きしない。エラー検出後でも初期角度の記録が残っていればbit0を保持できるが、実状態FAULTなので運転は許可しない。

常時送る校正/構成情報はこの1フレームだけとし、端位置・CPR・極性値・PID・LUT全量の周期送信案は取り下げる。追加データを後で取得する場合はデバッグ領域の別仕様とする。

例：M0 theta_init=+1.234 rad・追加データあり・ANGLE、M1未校正・追加データなし・UNINITIALIZED。

```text
D2 04 03 04 00 80 00 01
```

## FW・PC実装前に揃える接続・操作定義

状態の区分はユーザー確認済み。要求コマンド値・校正payloadの具体値は上記案を起点にする。実装に必要な残りの判断は以下。

| 項目 | 当面の方針・残る定義 |
|---|---|
| デバッグ接続先 | 現行PCツールはCAN RPC offset=0/16、RTTはST-Link serialで識別。これは通常CANの先頭軸番号0/2やFlash board_id=0/1と別。新FWのRPC要求/応答IDと、board_id保存・読戻し・UID照合を定義してから移行する |
| CAN送信元 | MainとPC-CANアダプターはどちらか一方だけを接続する。PCはMainの代役として同じ通常CAN指令・500 Hz・基板制御10 Hzを使う。所有権・競合調停・デバッグ専用の駆動セッションを新規追加しない |
| 初期化操作 | コマンドで開始し、中断後の再要求を許可する。同じINITIALIZEの周期再送では再実行しない。有効期間は現時点では未定とし、時間切れや永続保持を仮定しない。基準姿勢と追加構成データの対象集合は残る定義。現行のAB制御・校正手順は変更しない |
| エラー通知 | 1か所でも検出すれば基板全体をエラーにし、両軸を停止する。HW故障の診断を状態遷移の条件にしない。温度仕様・検出閾値/継続時間・共通0x000の原因番号は別途定義する |
| 校正と更新 | 校正通知は0x510/0x512へ移す候補とし、既存FW更新IDを維持する。Orion更新とステア独自更新の既存の方式差は、校正通知の移設と別の課題として扱う |

PCは2基板のFlash board_id照合、通常CAN送受信と基板別操作に対応した。実機は1基板のみで確認しており、2基板同時実機は未検証。

## RTTの縮小方針と現行実装との差

新設計のRTTはLUT等の保持データ・識別・必要な診断値の限定的な読出しに絞る。駆動、初期化開始、Duty/角度指令、生存通知による駆動維持をRTTの役割に含めない。書込み・リセット等を許可するコマンドは新たに仮定せず、必要な読出し項目と分割取得方式を定義してから実装する。
駆動・初期校正開始・停止はMainまたはその代役のPC-CANから同じ通常CANを使う。PC側のUI/接続先/ログは2基板を区別するが、新FWで通常駆動のために現行RPCのOPEN/PING/nonceを必須にしない。
ステアFWは旧駆動RPCを外部入口で拒否し、RTTをop0/1/9の読出しに限定した。PCは通常CANで駆動し、RTTは設定/LUT読出し等だけに使う。内部AB制御コードに旧op番号が残っていても外部からは駆動できない。

## ステアFW採用時の具体化

- 初期化は探索Duty15%、中立Duty上限20%、電流は保存上限と1 Aの小さい方を使用。既存区間3秒と探索距離上限を維持し、INITIALIZE継続中は区間を自動再開する。初期化中は独立操作として基板制御500 msを監視し、ANGLE/DUTY用の出力目標パケットは要求しない。
- 完了した初期校正は通常通信停止・上限0でも保持。中断・基板FAULT・リセットでは無効になる。時間失効は追加していない。有効期間の最終仕様は引き続き未定。
- 校正通知bit1は現在、軸の保存calibratedフラグを使用。NTC換算未確定の温度は無効値。実状態BOOT=0は予約で、周期通知開始後は1〜6を使う。
- ローカルエラーは0x000へ1回送信し、送信待ちは再試行する。他ノードの0x000受信でも両軸FAULTにし、反射通知しない。ロボット全体の原因コード解釈と停止の実機結合は未確認。
- Flash V4のboard_idは旧更新offsetとは別。旧ブート互換のV3レコードを各設定ページ先頭に残し、+0x800のV4追加レコードと同時確定する。既存FW更新ID・CRC・イメージ識別子は維持。
- 個体設定は旧CAN保守RPCのop33=board_id、34=有効軸/commissioned、35=保存電流上限。停止中の保存後に実リセットし、新IDを反映する。詳細とUID確認はステア側仕様へ一元化する。
