# Orionの電源基板とのCAN通信

参照したFWは `G474_Orion_main` の `500855e` と `F303_boost` の `8950ebc`。OrionはCAN1とCAN2へ同じ電源指令を送り、4WSの電源基板はCAN2に接続する。[CAN接続](../atlas_bringup.md#バスと車輪)

Orionで同じフレームを両バスへ送るのは `0x010` のON/OFFと保護値、`0x110` のキッカー系指令、`0x001` の電源リセット、`0x000` の共通エラー通知、ノード100宛て `0x611` のFW読取り照会。4WSでは電源基板宛ての送受信をCAN2に固定する。両バスのモーター停止フレームは接続先ごとに送る。4WSは受信した共通エラーを再送せず、Main内の停止処理に渡す。

## PowerOnの継続送信

- Orionの `actuatorPower_ONOFF()` は標準ID `0x010`、DLC 8。PowerOnは `00 01 00 00 00 00 00 00`、PowerOffは全byteが0。
- 通常運転ではTIM7割り込みのログ時刻判定で送信し、`MAIN_MODE_ERROR` 中はPowerOff、それ以外はPowerOnを送る。一時的な走行停止と電源断は別の扱い。通常ページは8割り込みごとでおよそ16 ms、TUIは50割り込みごとでおよそ100 ms。旧FWではUARTのページ設定によって送信間隔も変わる。
- FW更新ゲートウェイが有効な間はTIM7のこの処理より手前でreturnするため、通常のPowerOn送信が止まる。
- `F303_boost` はPowerOn受信で `sw_enable_cnt=200` に戻す。メインループで1ずつ減らし、0になると電源出力・昇圧PWM・キックPWMを停止する。通常ループは72 MHz、TIM1分周73、CNTを1000減らす構成から計算上およそ1 ms。200カウントは約200 msの目安で、処理遅延と搭載FWによる差は実機で確認する。明示的なPowerOffでも停止処理に入る。

## 指令とテレメトリー

| CAN ID | 方向 | Orion／電源FWでの用途 | 4WS Mainの実装状況 |
|---|---|---|---|
| `0x001` | Main→電源 | `5A A5` でリセット要求。参照電源FWでは異常時に再起動し、個別ACKは送らない | 起動時にCAN2へ送る |
| `0x010` | Main→電源 | PowerOn／Off、および保護値設定。設定はbyte 0がID、byte 1～4がfloat。Orionの起動時設定は最低15 V、最高35 V、最大50 A、FET・コイルの上限各90℃ | CAN2に20 ms周期でPowerOn／Off。最初のPowerOnより前にこの保護値を送る |
| `0x110` | Main→電源 | 昇圧目標、充電許可、ストレート／チップ選択、キック要求 | 給電準備では充電停止。テストモードでのみ100 Vの充電と50%のキックを操作できる |
| `0x215` / `0x216` / `0x234` | 電源→Main | バッテリー電圧／キャパシター電圧／バッテリー電流。参照電源FWはDLC 4でfloatを送る | CAN2でDLC 4・8を受理しUARTへ表示 |
| `0x224` / `0x244` | 電源→Main | 温度3値／状態フラグ。`0x244` の許可状態 `En` と出力ピン `Out` は別のビット | CAN2で受信しUARTへ表示 |
| `0x000` | 電源→Main | ノード100のFaultコード・付随値 | CAN2で電源Faultを識別し、最新値をUARTへ表示。共通Faultの停止処理にも渡す |
| `0x611` → `0x6C4` | 照会→応答 | ノード100のFWバージョン照会と応答 | USB-CAN直結は実機確認済み。Main RTT経由とOFWブート更新はホスト確認済み |

参照電源FWは起動時の接続・自己確認を終えてから周期通知を開始する。`canDataSender()` はメインループ6回を1巡として温度、バッテリー電圧、キャパシター電圧、電流、状態を順に送る。周期通知がない場合はPowerOnの有無に加え、給電・CAN配線・自己確認の状態も切り分ける。自己確認が実機でどこまで進んだかは未確認。[前回のCAN採取](../records/2026-11/uart_fixed_width_power_20261121.md)

## 4WSの給電と停止条件

- UARTと独立した20 ms周期でCAN2だけに送る。両バスのC610 0 Aとステアcoastを送信枠へ投入し、CAN2の電源リセット要求後に300 ms待ってから給電を準備する。ステアの同定・再起動には給電が必要な構成もあるため、応答完了前でもこの段階から通常給電を許可する。モーター操作は従来どおりステア起動確認の完了が条件。
- `0x110` の充電停止後、給電タイマーを更新するPowerOnを送る。参照電源FWの充電停止とPowerOffは、昇圧目標・昇圧PWM・キックPWM・給電タイマーをゼロにする。直接の昇圧目標コマンドは20 V未満が拒否されるため、目標ゼロには停止処理を用いる。給電中のMainはPowerOnで通常給電だけを維持する。キャパシターの残留電圧と、電源基板自身の起動時自己確認は別の状態。
- 起動確認の失敗、電源Fault、モーターデバッグFaultでPowerOffに切り替える。給電中に電源から昇圧PWM・キックPWM・充電許可のいずれかが立った通知を受信した場合はFaultを保持し、給電とモーター操作を止める。送信待ちのPowerOnは同じCAN IDで取り消す。
- ステアFW更新中は既存の操作禁止・0 A・coastを維持し、Flash書き込み用の通常給電を継続する。電源自身の更新時は電源出力を停止して状態を照合する。テスト操作と更新手順は[電源基板の操作](../power_bringup.md)を参照。

UART `KICKER` の `PW` はMainが最後に要求した給電状態。`En` と `Out` は電源基板の報告値で、実給電の確認にはこの応答が必要。

ソースの照合箇所はOrionの `Core/Src/main.c` の起動処理と `HAL_TIM_PeriodElapsedCallback()`、`Core/Src/actuator.c` の電源指令、電源FWの `Core/Src/main.c` のCAN受信・`connectionTest()`・メインループ、`Core/Src/can.c` の送信処理。バイト配置の共通仕様は[Orion CAN](../../specs/common/orion_can.md)を参照。
