# デバッグUART出力のOrion比較

2026-11-21のソース比較。参照元は `C:/Users/hiroyuki/STM32CubeIDE/workspace_1.17.0/G474_Orion_main` の `500855e`。以下は4WS MainのUART出力を設計するための整理。

## 現在の出力

OrionはLPUART1で、ページ見出し、ANSI色、バッテリー、エラーとページ別の診断を送る。通常ページの設定は60 Hz、TUIは10 Hz、走行CSVは250 Hz。通常ページのタイマー判定は500 Hz基準の整数分周で8周期ごと。起動時はFWのビルド日時、IMUとCANの初期化状況も表示する。ページ切替と走行CSVのヘッダーは `Core/Src/main.c:125, 475, 535, 554, 1246, 1373` にある。

比較時点の4WS MainはUART4（PC10 TX／PC11 RX）で、2 Mbps・8N1、TX DMA、受信は1バイト割り込み。100 msごとに `SW / CAN / CTRL / IMU / OLED` を1行出力していた。採用したページと端末操作は[UART4デバッグ](../drivers.md#uart4デバッグ)を参照。

## 同じ表示形式で実装できる部分

| Orionの表示 | 4WS Mainで使えるデータ・機能 |
|---|---|
| 起動メッセージとページ表示 | Mainの識別・ビルド日時、CAN／IMU／周辺基板リセットの初期化結果。ページ名、選択ページの強調、ANSI色、文字によるページ送り、区切りや符号付き数値は同じ形式にできる。通信成立と初期化完了はそれぞれ実状態を表示する。 |
| `SYSTEM` のCAN送信統計とSW診断 | CAN1／CAN2別のHAL投入成功、送信エラー、ソフトキュー退避・破棄。`SW ADC` は現在のADC生値とボタン判定を利用でき、電圧表示を揃える場合は参照電圧と換算条件を明記する。4WSでは受信破棄、FIFO喪失、bus-off、DIP、OLED、UARTエラーも表示できる。 |
| `KICKER` の `Batt(Pw)`、`Cap`、`FET/L1/L2` | 同じ電源基板をCAN2に接続している。`power_board_get_status()` が持つバッテリー電圧（`0x215`）、キャパシター電圧（`0x216`）、FET・コイル温度（`0x224`）は元と同じ単位で出せる。受信時刻を使い、未受信・期限切れを明示する。 |
| `DRV_HEADER` と周期ログの仕組み | ヘッダー付きCSV、時刻、行単位のサンプル取得は共通化できる。4WSの列と識別子は、OrionのCSVを読む既存ツールが誤解しないよう別に定義する。 |

`Batt=` はOrionでは駆動基板の `power_voltage[0]` を初期値20から平滑化した値。4WSは `VB[V]` としてCAN2電源基板の最新値を表示する。電流・電源状態の受信形式は[電源基板](../drivers.md#電源基板)を参照。

## 4WSの機器・制御に合わせて内容を変える部分

| Orionのページ・項目 | 4WS Mainでの扱い |
|---|---|
| `MOTOR`、`VEL`、走行CSVのモーター列 | 駆動はC610／M2006、操舵はAtlasの別系統。駆動側は目標・実ローターrpm、C610電流帰還のraw値と指令mA、帰還鮮度を表示できる。操舵側は目標・実角度、電流帰還、初期校正、状態、温度を別に表示する。C610ローターrpmを車輪側へ換算する場合は減速比と符号を定義する。Orionの `PwV`、`Vout`、エンコーダーノイズ、モーターパラメーターの `Rps`、モーター／ドライバー別温度には同じ取得元がない。Atlasの温度は無効値を明示し、現在のステアFWでは全軸無効を実機で確認済み。 |
| 車輪の並び順 | `g0/g1` はCAN1・ステアID 0のM0/M1・C610 ID 1/2。`g2/g3` はCAN2・ステアID 1のM0/M1・C610 ID 3/4。OrionのRF/RB/LB/LF表記と対角輪集計を使うには、4WS側の物理位置・符号の対応を確認する。 |
| `SYSTEM TIME`、`TO`、`Err`／`ErrLatest` | OrionはTIM7の7区間、POWER／左右BLDC／SUBのタイムアウト、最新エラーと復帰回数を表示する。4WSはTIM6の呼出し回数・オーバーラン・最大実行時間・割り込み進入遅延、電源／ステア／C610の鮮度、周辺基板リセットとモーターデバッグ状態に合わせる。電源とステアは同じ `0x000` を使う。詳細Faultを表示するには発信元とコードの意味を識別できる条件、履歴の保持、復帰の定義が必要。 |
| `ODOM`、`MOTION`、`VEL` の姿勢・機体制御 | 同じICM-20602から3軸の加速度・角速度とセンサー温度を取得できる。現行APIはセンサー座標系の未校正値。Orionの `yaw`、機体速度、オドメトリー、Visionとの差分、機体制御の目標やゲイン表示は、機体座標・姿勢推定・4WS運動学と通常制御の実装後に対応する。 |
| `CMD`、`LATENCY`／`CAM`、`UART RAW` | OrionのCM4通信はUSART2。4WSはCM4 SPIを予定し、実通信は未実装。受信バイト列、CRC、鮮度、通信頻度、Vision・指令・カメラ情報はSPIとコマンドの定義後に対応する。UART4自体のドライバ統計と、CM4通信の統計は別の項目にする。 |
| `DRIBBLER`、`KICKER` の動作欄、`MOUSE` | 4WSで有効なドリブラー・キック・ボール検出・マウスオドメトリーの取得経路を個別に確認する。現行の `PHOTO_0/1` はADC取得に未登録、ESC PWMのドリブラー出力は未実装。旧CANデコーダーに項目があるだけでは装備・稼働を確認したことにならない。電源の測定欄は表示できる。 |

## 採用範囲と追加時の条件

- ページ切替は数字、CR/LF、DELなどの読取り専用入力を揃えられる。Orionの `q/a/w/s` はゲイン変更、`t` はCM4テレメトリーの切替であり、4WSの出力形式の同等化とは別に扱う。
- 今回のページは従来の100 ms周期と固定小数点整形を採用する。走行CSVは保留。高頻度ログを追加する場合は、実装後にCAN欠落と制御遅延を測る。
- 未受信・期限切れ・未実装を数値の `0` と区別する。温度や電圧の警告色に用いるしきい値は機器ごとに定義する。OrionのBLDC過熱判定をC610やAtlasに適用する条件は現行仕様にない。
